# Roadmap

> Phases from SPEC §23. Each phase starts in plan mode, ends with a summary + manual test checklist, and needs explicit approval before the next (CLAUDE.md).
> **Every phase's definition of done includes:** `pnpm typecheck`, `pnpm lint`, `pnpm test` and pgTAP all green with output shown; RLS isolation tests for any new table; docs/ADRs updated; UI follows [`design.md`](./design.md) with loading/empty/error states.

| Phase | Deliverables | Definition of done |
|---|---|---|
| **1. Foundation** | Next.js app (strict TS, Tailwind with design tokens, ESLint incl. service-key import rule), Supabase local stack, real migrations from the draft (reference data, identity, businesses, members, RLS helpers), seed, profile bootstrap trigger, phone OTP + email login (Mock SMS via Send SMS Hook), role guards in `src/server/auth`, env validation, CI pipeline, `docs/env.md`, `docs/testing.md` | Can sign up with phone OTP locally; profile auto-created; pgTAP proves business A/B isolation for all Phase 1 tables; meta-test "RLS on every table" passes; CI green on a PR |
| **2. | **3. ## Major technical risks

| # | Risk | Likelihood / impact | Mitigation |
|---|---|---|---|
| 1 | **RLS mistake leaks tenant data** | Med / Critical | Deny-by-default; definer functions for writes; composite FKs; mandatory per-table isolation tests; CI meta-test for RLS enabled; no service key in request paths |
| 2 | **Availability logic drift** between TS listing and SQL acceptance | Med / High | DB is the final arbiter; parity tests with randomised fixtures; one shared fixture set |
| 3 | **Timezone/DST bugs** once other countries launch | Low now / High later | All storage UTC; wall-clock only in hours tables; DST unit tests using a DST zone (e.g. Europe/London) from day one |
| 4 | **SMS cost & OTP abuse** (SMS pumping) | High / Med | Per-phone and per-IP caps in hook, Turnstile, alerts on SMS spend, country allowlist for OTP |
| 5 | **Mobile Money integration complexity** (async approvals, lost callbacks) | High / High | Interface + mock first; webhook inbox + reconciliation polling; holds with expiry |
| 6 | **WhatsApp Business Platform approval delays** | Med / Low | SMS is the baseline; WhatsApp added when approved |
| 7 | **Latency from Ghana** to EU-hosted DB/functions | Med / Med | Co-locate Vercel functions with DB; cache public pages; measure in Phase 1; low-JS pages |
| 8 | **Low-end devices / poor networks** hurt conversion | High / Med | Server Components, JS budgets, client-side image resize, skeletons, Lighthouse CI on throttled profile |
| 9 | **Supabase/Vercel free-tier limits** (pausing, cron, bandwidth) | Med / Med | Staging may pause; production on paid Supabase from launch; pg_cron avoids Vercel cron limits |
| 10 | **Scope creep** for a solo developer | High / High | MVP exclusions list in `product.md`; one phase at a time with approval gates |
| 11 | **Regulatory** (Act 843, payments licensing) | Med / High | Minimisation, consent records, audited PII access; no platform-held funds in MVP; DPC registration and legal review in Phase 11 |
| 12 | **Name/trademark conflict** found late | Med / Med | Formal clearance before buying domains/branding (Phase 1 kickoff); name is a config/brand token, not hard-coded |
