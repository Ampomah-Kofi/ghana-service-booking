# API v1

Base URL: `{SITE_URL}/api/v1`. Machine-readable description: [`/api/v1/openapi.json`](../../src/server/api/openapi.ts) (OpenAPI 3.0, generated from the Zod schemas in `src/schemas/api-v1.ts`, so it can't drift from the code).

## Conventions
- JSON, `snake_case` keys. Money is `{ "amount_minor": 5000, "currency": "GHS" }` (minor units: pesewas). Times are ISO-8601 UTC; businesses also expose their IANA `timezone`.
- **Auth:** `Authorization: Bearer <Supabase access token>` for signed-in callers (mobile apps). Public endpoints work without it. No cookies, so no CSRF surface. RLS applies to every call.
- **Errors:** `{ "error": { "code": "VALIDATION", "message": "…", "details": … } }` with HTTP 401/403/404/409/422/429/500.
- **Caching:** identical-for-everyone responses carry `Cache-Control: public, s-maxage=…`. Anything with a Bearer token or coordinates is `private, no-store`.
- **Versioning:** additive changes stay in v1. Breaking changes go to `/api/v2`, run side by side (docs/architecture.md §12).

## Endpoints

### `GET /categories`
Active categories in display order. `{ data: [{ id, name, slug }] }`.

### `GET /search`
| Param | Example | Notes |
|---|---|---|
| `q` | `Barber in East Legon`, `Nails near me`, `fade` | "what in where" is understood; "near me" needs `lat`/`lng` |
| `where` | `Kumasi` | Overrides the place in `q` |
| `category` | `photography` | Category slug |
| `lat`, `lng` | `5.6037`, `-0.187` | Sorts by distance within 25 km |
| `sort` | `relevance` \| `distance` \| `newest` | |
| `page`, `page_size` | `1`, `20` | `page_size` ≤ 50 |

Response: `{ data: BusinessCard[], meta: { total, page, page_size, interpretation, notice, needs_location } }`.
- `interpretation` says how the query was understood (category, place, near me, free text).
- `notice` is set when the search was widened (e.g. "No braids & locs in Accra yet. Here are other places.") or a place wasn't recognised.
- `needs_location: true` means "near me" was asked without coordinates: ask the device for location and retry.

`BusinessCard`: `id, slug, name, image_url, category, place, starting_price { amount_minor, currency, is_from }, rating, next_available_at, distance_km`. `rating` stays `null` until reviews exist (Phase 7), and `next_available_at` stays `null` until the background job that computes it exists (Phase 8).

### `GET /businesses/{slug}`
Public profile: details, location (area/city/region/landmark/coordinates), contact, logo and photo URLs, active services (with `price`, `price_type`, `duration_minutes`, `staff_ids`), team, and weekly `hours` (`weekday` 1 = Monday, local times, `closes` may be `24:00`). `404` for drafts and suspended businesses, unless the Bearer user is on that business's team.

### `GET /businesses/{slug}/availability`
Query: `service_id` (required), `staff_id` (a staff id or `any`, default `any`), `from` (local date `YYYY-MM-DD`, default today in the business's timezone), `days` (1–14, default 7).
Returns `data: [{ date, slots: [{ starts_at, staff_ids }] }]` and `meta: { timezone, last_bookable_date }`. `staff_ids` lists who is free, in the order "any available" tries them (fewest booked minutes that day first). Computed by the same engine as the website; cached for 10 seconds.

### `POST /appointments` (Bearer)
Header `Idempotency-Key` (8–100 chars, e.g. a UUID) is **required**: retrying with the same key returns the original booking instead of a second one.
Body: `business_id`, `service_id`, `staff_id` (id or `any`), `starts_at` (ISO-8601), `customer_name`, optional `customer_phone` (defaults to the account's phone; one is required) and `note` (≤ 500).
`201` with `data: Appointment`. Errors: `401` not signed in, `409 CONFLICT` the time was just taken (or is outside hours), `422` invalid, too soon (minimum notice) or too far ahead, `429 LIMIT_REACHED` more than 10 bookings in an hour.

### `GET /me/appointments` (Bearer)
`data: { upcoming: Appointment[], past: Appointment[] }`. Upcoming is soonest first; past (including cancelled) is latest first.

### `POST /appointments/{id}/cancel` (Bearer)
Optional body `{ reason }` (≤ 200). Allowed until the business's cancellation window before the start (`can_change` tells you). `404` if it isn't your booking, `409` if it's too late or already cancelled.

### `POST /appointments/{id}/reschedule` (Bearer)
Body `{ staff_id, starts_at }`. Atomic: the old booking is cancelled and the new one created in one transaction; if the new time is taken, nothing changes (`409`). Returns the **new** appointment (its id differs).

`Appointment`: `id, status (pending|confirmed|arrived|completed|cancelled|no_show), source (online|manual|walk_in), starts_at, ends_at, business { id, name, slug, timezone }, service { id, name }, staff { id, display_name }, price { amount_minor, currency, type }, deposit, final_price, payment_status, customer { name, phone }, note, cancellation_reason, can_change`.

## Business side (Phase 6)
Members only: a Bearer token of someone on the business's team. Anyone else gets `404`, so drafts stay hidden.

### `GET /businesses/{slug}/appointments`
Query: `from` (local date, required), `days` (1–31, default 1), `include_cancelled` (`true|false`). Returns appointments overlapping those days, soonest first, plus `meta: { timezone, can_manage, own_staff_id }`. Owners and managers see everyone's; staff see only their own.

### `POST /businesses/{slug}/appointments`
A phone booking or a walk-in. Body: `service_id`, `staff_id`, `walk_in` (default false), `starts_at` (required unless walk-in, which starts now), `client_id` or `client { name, phone }` (a known phone reuses that client; an anonymous walk-in needs neither), `note`, `allow_outside_hours` (default false).
- Staff may add only for themselves (`403` otherwise).
- `409` means an overlap, or outside hours/time off without the override. Overlaps can never be overridden.

### `POST /appointments/{id}/status`
Body: `status` (`confirmed|arrived|completed|cancelled|no_show`), optional `reason` (≤ 200), optional `final_price_minor` (only with `completed`). The allowed changes and time rules are in [architecture §6](../architecture.md). Completing early records the real end time. `409` if the change isn't allowed now; `404` if it isn't your business's or your own appointment.

## Favourites and reviews (Phase 7)
Reviews come only from the customer of a **completed** appointment (one each), can be edited for 14 days, get at most one public reply from the business's owners/managers, and can be reported. Hidden or removed reviews leave the public list and the rating. A review object: `{ id, business_id, appointment_id, author_name ("Kofi A." or "Former customer"), mine, service_name, staff_name, visited_on, rating (1-5), body, status, reply: { body, at } | null, created_at, editable_until }`.

### `GET /me/favorites` (Bearer)
Saved businesses as result cards (same shape as `/search`), newest saved first. Unpublished businesses drop out. Private: businesses never see who saved them.

### `PUT /me/favorites/{businessId}` · `DELETE /me/favorites/{businessId}` (Bearer)
Save or unsave; both idempotent. Returns `{ data: { business_id, saved } }`. Unknown or unpublished business → 404.

### `GET /businesses/{slug}/reviews?page=&page_size=`
Published reviews, newest first. `meta: { average, count, distribution: [1★ … 5★], page, page_size }`. Cached 60 s when anonymous.

### `GET /me/reviews` (Bearer)
Your reviews in any status, with `business: { name, slug }`.

### `POST /appointments/{id}/review` (Bearer)
Body `{ rating, body? }`. 201 with the review. 404 not your booking · 409 already reviewed · 422 not completed yet.

### `PATCH /reviews/{id}` (Bearer)
Author only, while published and within 14 days. Body as above.

### `PUT /reviews/{id}/reply` (Bearer, owner/manager)
Body `{ body }`. Posts or replaces the one reply. Staff → 403; another business → 404.

### `POST /reviews/{id}/report` (Bearer)
Body `{ reason: spam | offensive | not_genuine | private_info | other, details? }`. 202. Once per person (409); not your own (422).

`GET /businesses/{slug}` now also returns `rating: { average, count } | null` and `photos[].service_id`.

## Profiles and prices (after Phase 7)
- `GET /businesses/{slug}` adds `social: { instagram, tiktok, x, facebook, youtube, website }` (full https links or null).
- Service `price_type` may be `on_request`: `price.amount_minor` is 0 and means "agreed with the business"; show "Price on request". Search cards ignore these when computing `starting_price` (null if every service is on request).

## Notifications (Phase 8)
In-app messages for bookings (yours, and your business's if you're a member). Texts and emails are sent by the platform; the API manages the inbox and preferences.

### `GET /me/notifications` (Bearer)
Due messages only (a reminder appears at its time), newest first: `{ id, template, title, body, href, audience: customer|business, at, read }`, plus `meta.unread`. `href` is a web path; apps map `/bookings/{id}` and `/dashboard/{business}/appointments/{id}` to screens.

### `POST /me/notifications/read` (Bearer)
Body `{ ids? }`. Omit `ids` to mark everything read.

### `GET | PUT /me/notification-preferences` (Bearer)
`{ text: sms | whatsapp | none, email: boolean }`. One text channel per message (ADR-0013); in-app always arrives.
